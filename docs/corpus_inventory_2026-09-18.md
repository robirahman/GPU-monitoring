# Corpus inventory, 2026-09-18

Generated by `PYTHONPATH=. python3 scripts/corpus_inventory.py`. Re-run it rather
than trusting these numbers after the next collection.

Three things to read carefully before quoting any of it:

* **File level and deduplicated differ by a third.** 10,840 parquet files hold
  6,602 distinct `(run_id, gpu_uuid)` streams, because the same stream is written
  into more than one directory and `load_all_data` collapses those on
  `(ts, run_id, gpu_uuid)`. The deduplicated block is the corpus. 90,040
  file-level stream-minutes are really 59,657.
* **Stream-minutes are not wall-clock.** A 16-chip TPU cell running for 10
  minutes contributes 160 stream-minutes. Across distinct runs the corpus is
  325 wall-clock hours; as per-device telemetry it is 994 stream-hours.
* **Multi-machine is measured, not inferred from the label.** The chip count in a
  scope name does not tell you how many hosts it used: `tpuT16` runs are
  `w0..w3 x c0..c3`, four hosts of four chips, while `tpuT8` runs are
  `w0c0..w0c7`, ONE host of eight -- they ran on differently-shaped v5e slices.
  Host count comes from `hostname` (or the `_w<W>c<C>` worker token). The one
  place the label still overrides the measurement is `s1_`/`s8_`: those share a
  run_id across both machines with no node component, so each node is running
  its own independent single-node job and a naive host count would call them
  multi-node. `classifier/multinode_features.py` resolves it the same way.
