## Why the starved cells change name

`adversarial_L_diluted_*` and `adversarial_K_online_learning` are listed as `_mw8`. Re-running the original command reproduces the starvation -- `num_workers=0` puts `Resize(224)` on one CPU thread and the GPU waits, which is how the archived runs managed four batches in 324 s. The `_mw8` cells pass `--num-workers 8` and are GPU-bound. That makes them a different workload, so they carry a different label and must not be pooled with the originals, which stay in the registry as what the camera-ready measured.
